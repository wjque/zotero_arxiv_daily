## Fixed

- Fixed Zotero Local API incremental synchronization when its deleted-record endpoint returns HTTP
  404. The adapter now obtains and atomically reconciles a complete item/collection snapshot, so
  deleted local records are removed rather than silently retained and a trustworthy profile snapshot
  can be created.

- Converted arXiv publication instants to `Asia/Shanghai` before deriving browser filter dates,
  preventing UTC/local-midnight misclassification.
- Ensured fully suppressed or empty eligible batches make no provider request and failed, skipped,
  or partially deployed runs do not advance recommendation history.
- Fixed state-branch persistence after production smoke run `30732033140` exposed that the new
  local worktree branch was based on `main`, causing a non-fast-forward push after Pages deployed.
  Persistence now bases the worktree explicitly on `origin/state` when prior state exists.
- Fixed empty weekend batches by performing a bounded seven-day backfill when migrating an empty
  v1/v2 candidate state, then using successful-publication history to exclude already recommended
  IDs before any model work. ArXiv revision numbers are now preserved explicitly in state v3.
- Fixed feedback adjustments being applied only to shortlist construction by carrying the same
  local adjustment into final selection.
- Fixed stale model proposals for revised papers by including bounded candidate content, revision,
  and update metadata in the cache fingerprint. Empty or malformed structured model responses now
  retry within the existing request budget, and the DeepSeek adapter explicitly disables thinking,
  requires a JSON object, and bounds output tokens.
- Fixed the prompt's concrete JSON-example identifier after scheduled production run `30746199306`
  rejected an unrequested model ID. The prompt now requires verbatim candidate IDs without showing
  a copyable paper identifier; strict local allowlisting and bounded retries remain in force.

## Compatibility and Migration

- The proposed plan requires backward-compatible readers for v0.1.0 profile, arXiv state, encrypted
  publishable data, and feedback artifacts. No runtime schema or production behavior changed in
  this documentation-only update.
- Added exact v0.1.0 readers for remote-profile v1, arXiv-state v1, and publishable-site v1. New
  output uses remote-profile v2, arXiv-state v2, recommendation-set v2, publishable-site v2, and
  recommendation-history v1; feedback schema remains unchanged.
- Existing profiles migrate to empty watchlists. Rebuilding and explicitly republishing the
  protected profile activates configured v2 watchlists; no raw Zotero data crosses a new boundary.
- Existing arXiv-state v1/v2 files remain readable. Their candidates seed state v3 on the next
  successful retrieval; an empty legacy candidate list triggers the bounded backfill atomically.
