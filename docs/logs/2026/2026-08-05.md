# 2026-08-05

## Summary

- Hardened the active v0.2.0 release candidate in response to the zero-overlap evaluation result,
  unauditable LLM efficiency measurements, and public plaintext workflow-state exposure. The
  immutable v0.2.0 plan was not changed.

## Added

- Added AES-GCM encrypted workflow-state bundles with validated required/optional file allowlists,
  atomic owner-only local writes, `state encrypt` / `state decrypt` commands, and a dedicated
  `ZAD_STATE_ENCRYPTION_KEY` configuration value distinct from the Pages passphrase.
- Added one-time legacy state migration and a manual-only, lease-protected encrypted-root history
  purge action. ADR-0001 defines the key, migration, rollback, and exposed-history requirements.
- Added candidate-positive and candidate-negative coverage plus candidate-conditional Recall to
  ranking metrics. Shadow comparison and the coarse Recall@60 gate now treat zero candidate-label
  overlap as unavailable rather than ranking quality evidence.
- Added provider-neutral completion usage, measured token/latency/cost manifest fields, privacy-safe
  manifest history, and `evaluate efficiency` median comparison. The comparison fails closed when
  actual token usage is missing or the 25% output-token target is not met.
- Added a bounded categorical preference-context allowlist and ADR-0002. Only up to four approved
  signal names can reach `explain-v1`; `judge-v1` remains limited to public candidate metadata.

## Changed

- The production workflow writes only `state.enc.json` to the `state` branch and restores state only
  after authenticated decryption and schema validation. Missing state branches may initialize empty;
  invalid, missing, or undecryptable persisted state fails closed.
- Manual refinement canaries retain a separate preference-context approval input. Scheduled runs keep
  refinement and preference context disabled, and manifests record whether the context was enabled.
- README and v0.2.0 release notes now describe conditional Recall interpretation, measured efficiency
  comparison, encrypted state operation, and the explicit history-purge precondition.
