# 2026-08-20

## Summary

- Implemented V030-M3 controlled candidate coverage on
  `feature/v0.3-controlled-coverage` while preserving v0.2.1 as the production discovery default.
- Implemented the local/remote interest-profile trust boundary on `feature/v0.3-serving-profile`;
  no GitHub Secret or production policy was changed.

## Added

- Added a deterministic planner that maps allowlisted protected-profile facets to at most four
  cross-category arXiv bridge queries and accepts bridge candidates through local public-text
  matching.
- Added a `controlled-shadow` retrieval mode that requires a separate ignored candidate-state path
  and reports query, request, and bridge-candidate counts.
- Added synthetic bridge-paper, empty-profile, malformed-metadata, deduplication, partial-failure,
  ordering, query-budget, request-budget, and candidate-budget coverage.
- Recorded the privacy and activation boundary in ADR-0009.
- Added separate owner-only local-interest and schema-v5 remote-serving profile files. The serving
  profile carries bounded long-term/recent HMAC features, anonymous paper prototypes, protected
  exact watchlists, controlled facets, categories, and a key-pair verifier without plaintext
  free-form interests, watched names, or paper identities.
- Added a separate `ZAD_PROFILE_FEATURE_KEY` configuration and GitHub Secret publication path with
  preflight pair validation, distinct Secret names, standard-input transport, and fail-closed remote
  matching before any model call.
- Added ADR-0010 for the keyed serving-profile trust boundary, offline-host behavior, key rotation,
  migration, and rollback.

## Changed

- Refactored retrieval to consume typed discovery queries, reserve a bounded bridge-candidate budget,
  reject oversized provider pages, and abandon partial results on any provider failure.
- Kept the scheduled workflow on the exact released category-only path; controlled discovery remains
  local shadow behavior pending V030-M6 operator approval.
- Split profile construction into a complete local aggregate and privacy-minimized remote projection,
  upgraded item-digest extraction, and separated long-term, recent, controlled-facet, anonymous
  prototype, and exact-watchlist scoring components.
- Kept schemas v1-v4 readable without a feature key and preserved protected schema-v5 lexical counts
  in the explicit v0.1.2 ranking rollback path. Model requests continue to contain public candidate
  evidence only.

## Compatibility and Migration

- No persisted schema changed. Existing public candidate-state files and the v0.2.1 discovery path
  remain valid.
- The preceding no-schema-change statement applies to the V030-M3 discovery slice. The later
  serving-profile slice adds opt-in remote-profile schema v5 while retaining exact v1-v4 readers.
- Remote arXiv requests contain only category and date constraints. Protected facet values remain
  local and no private profile content is added to candidate or browser artifacts.
- No existing profile, Zotero, feedback, candidate, recommendation-history, encrypted-state, or
  browser file is migrated automatically. Existing v1-v4 GitHub profile Secrets continue to run;
  schema v5 becomes active only after an explicit local build and publication of the matched profile
  and key. A failed or transiently mismatched v5 run leaves the previous deployed site usable.
