# 2026-08-06

## Summary

- Fixed the v0.2.0 release-candidate CI type-check failure and implemented the explicitly authorized
  smaller release contract: interest-only coarse screening, bounded abstract-quality and project-page
  refinement, and feedback collection without feedback learning or provisional metric gates.

## Added

- Added positive-only reachability evidence for approved project-page URLs explicitly supplied in
  public arXiv abstracts. The checker revalidates redirects, bounds requests, caches daily results,
  retains no response body, and degrades unavailable evidence to unknown.
- Added ADR-0004 for the abstract-link request boundary and deterministic unit/integration coverage for
  extraction, validation, redirects, failures, cache reuse, and refined-rank contribution.
- Added an explicit manual `v0.1.2` production rollback mode that runs the frozen scoring, quotas,
  diversity, baseline proposal prompt, and final ordering through the current encrypted state and
  Pages deployment boundaries. Scheduled runs remain on v0.2 and manifests identify the active mode.

## Fixed

- Replaced invalid inheritance in the measured refinement provider test double with composition. Its
  `ProviderCompletion` return type now satisfies strict typing without changing the production provider
  contract or test behavior.

## Changed

- Replaced the authorized v0.2.0 plan with a concise interest-screening and feedback-foundation
  contract. NDCG, negative-label rate, Recall, token reduction, latency, and cost remain observable but
  no longer approve or block the release.
- Removed feedback features, penalties, cache inputs, and model relevance signals from v0.2.0 coarse
  and refined ranking. Daily feedback ingestion and successful-publication impressions remain
  append-only encrypted state for v0.2.1 or later.
- Replaced `judge-v2` with `judge-v3`, which evaluates only preliminary scientific-quality dimensions
  supportable by complete public titles and abstracts. Project-page availability is validated locally
  and added independently during fine ranking.
- Made shadow metrics observation-only and changed weight activation to an explicit operator action
  without an eligible-report requirement.
- Froze the v0.2.0 release documentation after the accepted production canary and completed rollback
  rehearsal: README now describes the release, and CHANGELOG carries the 2026-08-06 release date.

## Removed

- Removed weekly feedback-to-score activation, the workflow activation step, its CLI command, its
  unused recommendation/evaluation feedback-state arguments, and its configuration variables.

## Compatibility and Migration

- Feedback schema v1 and v2 remain readable. Historical adjustment and activation fields are preserved
  during writes but are no longer consumed by ranking.
- Existing `judge-v2` cache entries are intentionally bypassed by the `judge-v3` namespace. Publishable
  schema v1-v4 and encrypted state remain unchanged.
- Operators must stop using `feedback activate`, the removed feedback-activation environment variables,
  recommendation/evaluation `--feedback-state`, and activation `--shadow-report` arguments.
