# 2026-08-03

## Summary

- Refined the active v0.2.0 requirements after reviewing the role of the user's preliminary curated
  paper collection and the operational cost and stability of feedback-driven learning. V020-M1
  remains pending and no runtime implementation started.

## Changed

- Defined the curated corpus as an evolving local judgment source rather than a fixed dataset.
  Additions, corrections, reason changes, and explicit unlabeling will retain lineage, while each
  reproducible evaluation pins an immutable corpus revision, digest, cutoff, and split identities.
- Changed personalized screening-criteria activation from a possible daily update to a guarded
  weekly cadence. Feedback events may still be ingested on scheduled runs, but daily recommendations
  use the last successful weekly aggregate snapshot.
- Added requirements for configurable weekly eligibility in `Asia/Shanghai`, deterministic event
  cutoffs, minimum-sample no-ops, stable-anchor and rolling evaluation windows, accumulated-event
  recovery after missed or failed runs, atomic activation, versioned rollback, and injected-clock
  boundary tests.
- Kept automatic weekly learning limited to bounded derived preference aggregates. Prompt, rubric,
  security, exploration, and production-weight changes remain separately versioned and explicitly
  activated.

## Compatibility and Migration

- This is a documentation-only requirement update. It changes no schema, configuration, runtime
  state, deployment behavior, model cost, trust boundary, or private corpus content. Expected weekly
  activation state and correction lineage remain future V020-M1/V020-M3 implementation work.

## V020-M3 Foundation

- Started the v0.2 feedback-loop migration with a local append-only v2 ledger. It preserves legacy
  v1 adjustments as explicitly marked legacy evidence, distinguishes impressions from outcomes,
  supports correction lineage and categorical negative reasons, and has a guarded atomic weekly
  activation primitive with deterministic no-op behavior for insufficient samples.
- Completed V020-M3 by routing Issue ingestion through the v2 ledger, configuring the seven-day

  recording impressions only after successful Pages deployment, and exposing position-conditional

## V020-M4 Foundation

- Introduced a versioned normalized coarse-ranking feature and weight-set contract. Interest,
  recency, feedback, and identity contributions are bounded; explicit negative feedback uses a
  capped penalty and missing feedback is not treated as negative. Existing quotas, diversity,
  exclusions, and deterministic ordering remain in place while offline evaluation gates are added.

## V020-M5 Implementation

- Completed the provider spike after explicit user authorization for a read-only public-metadata
  boundary. The Semantic Scholar unauthenticated probe returned HTTP 429, so it is not selected for
  scheduled enrichment. OpenAlex exact-DOI lookup was selected for bounded citation/reference,
  open-access, and retraction context; public arXiv DOI values are retained in candidate state schema
  v4 with exact readers for schemas v1–v3.
- Added provider-neutral context values, provider/version-scoped evidence-cache keys, bounded OpenAlex
  top-K enrichment, and the `evidence enrich` CLI command. The command sends only public candidate
  DOI values, caches local ignored TTL evidence, and degrades missing DOI, identity mismatch, timeout,
  rate limit, malformed response, or outage to `unknown` without changing recommendation output.
- Added a GitHub structured repository-facts adapter that accepts only a pre-verified HTTPS
  `github.com/owner/repository` association. It validates the returned repository identity and exposes
  bounded license, archive, Wiki-documentation, and recent-maintenance facts. It does not search for
  associations, fetch README/source content, or connect to ranking/site output.
