## v0.2.1 Quality-First Implementation

### Added

- Implemented the v0.2.1 public quality-evidence boundary. Bounded ar5iv extraction supplies only
  method, implementation/evaluation, and limitations sections; explicitly linked GitHub evidence
  inspects root structure metadata without downloading or executing repository code.
- Added immutable, explicitly approved quality-reference profiles with allowlisted traits, explicit
  feedback aggregation, reversible approval/rollback, aggregate-only prompt projection, and encrypted
  workflow-state inclusion.
- Added strict sub-24-hour metadata-only validation with encrypted privacy-safe manifests. The
  validation workflow has no model, site build, Pages upload/deployment, publication history,
  impression, or pending-state path.
- Added publishable schema v5 reporting scientific quality, uncertainty, implementation evidence,
  evidence fields, and bounded provenance separately, with exact v1-v4 readers.
- Added ADR-0005 for public quality evidence and quality-reference boundaries and ADR-0006 for the
  deployment-timestamp validation state machine.

### Changed

- Activated `quality-first-v1` production weights: interest `0.40`, recency `0.05`, watched identity
  `0.10`, scientific quality `0.35`, and project/implementation evidence `0.10`. The known built-in
  `coarse-v1` pointer migrates once; custom operator versions remain active.
- Moved project-page reachability into coarse screening and expanded fine-screening cache identities
  to cover the exact bounded public evidence and approved quality-reference payload.
- Advanced the authoritative application version to `0.2.1` and documented quality-profile operation,
  validation behavior, compatibility, privacy, and rollback boundaries.

### Fixed

- Corrected publication-history promotion so only normal successful deployment or verified next-run
  reconciliation replaces active history. Unpublished prepared state no longer suppresses papers;
  successful-publication impressions remain idempotent.
- Made artifact inspection ignore tracked paths deleted in the current worktree, allowing schema test
  fixture renames to be verified before commit without weakening content scanning.

### Tests and Verification

- Passed Ruff formatting and lint, strict mypy over 114 source and test files, Ruby YAML parsing,
  `git diff --check`, and 210 offline unit, contract, and integration tests.
- Passed four Playwright desktop/mobile Chromium tests for encrypted schema-v5 rendering, separated
  evidence display, and unsupported-schema rejection.
- Built the `0.2.1` source distribution and wheel in temporary storage and passed the artifact safety
  and static-site size/privacy checks. A source-tree secret scan found only the intentional synthetic
  Zotero normalization fixture covered by the artifact check's JSON-only export rule.

### Compatibility and Migration

- Protected bundles accept versioned quality-profile and validation-manifest files without changing
  the AES-GCM envelope schema. Legacy deployment receipts without a successful deployment timestamp
  conservatively select publication once. Publishable v1-v4 readers and the v0.1.2 ranking rollback
  remain available.
