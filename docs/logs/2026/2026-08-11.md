# 2026-08-11

## Summary

- Completed the local quality-reference review follow-up for v0.2.1 without expanding the reviewed
  sample or activating production state.

## Added

- Added privacy-safe `quality-profile inspect` and reversible `quality-profile clear-approval`
  operations. Clearing the first activation retains every immutable registered version and is
  idempotent when no profile is approved.
- Added a manually dispatched, `production`-environment-protected quality-profile maintenance
  workflow. It generates unapproved candidates from an environment secret, separates approval from
  generation, shares the daily production concurrency lock, and persists only encrypted protected
  state through normal fast-forward pushes.
- Added a typed, versioned quality-reference policy registry. Policies assign roles to complete
  fields rather than individual papers or traits, carry their own judge contract, and can be selected
  during candidate generation without changing workflow code.

## Changed

- Upgraded new quality profiles to schema v2 and `judge-v4`. Relative support is explicitly
  non-scoring; research problems and motivations stay local and never enter model payloads;
  methodology and evidence standards are optional positive references whose absence is not negative;
  tolerated limitations are non-scoring context whose empty value means unspecified. Quality
  references can no longer satisfy candidate `evidence_fields` requirements.

## Fixed

- Corrected the TAPIR paper identity in the private reviewed examples and review report from an ICCV
  DOI-derived value to arXiv `2306.08637`. Source identities remain excluded from the digest; the
  candidate version changed to `quality-profile-31e65ca5be3632bc` only because schema v2 includes the
  interpretation policy and its immutable fingerprint in the profile identity.

## Compatibility and Migration

- The encrypted state-bundle schema remains unchanged. Existing quality-profile schema-v1 state is
  read without destructive rewriting and upgrades its registry envelope on the next explicit
  mutation while retaining `judge-v3`; new profiles persist schema v2, a registered policy version,
  and a validated policy fingerprint. Production maintenance requires a new
  `QUALITY_PROFILE_EXAMPLES` secret in the protected `production` environment; no model, Pages,
  feedback-ingestion, or publication state is involved.
