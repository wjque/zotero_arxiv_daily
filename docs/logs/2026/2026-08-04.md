# 2026-08-04

## Summary

- Continued the active v0.2.0 personalized-ranking plan without changing production activation,
  publishing runtime data, or adding a new approved trust boundary.

## Added

- Added applicability-aware normalized ranking feature groups, immutable local weight-set registry
  definitions, reversible active pointers, score contributions, and source-aware exploration reserve.
- Added a local `evaluate snapshot` / `evaluate shadow` workflow. It freezes corpus inputs, compares
  the frozen v0.1.2 scorer with the active local weight set, reports aggregate Recall/Precision/NDCG,
  negative-label rate, calibration/diversity/coverage metrics, and feature-group ablations, and writes
  owner-only ignored reports without changing runtime recommendation state.
- Added a gated two-stage LLM recommendation path. `judge-v1` supplies bounded quality and uncertainty
  features to local selection; `explain-v1` produces summary/reason/limitation text only for final
  selections. Judge and explanation caches remain separate and validated before they are written.
- Added publishable-site schema v4 with an optional limitation note and retained exact v1-v3 readers.

## Changed

- Corrected normalized coarse ranking to classify core, adjacent, and exploration candidates correctly.
  Missing or inapplicable evidence is excluded from score normalization rather than interpreted as zero.
- The daily workflow persists the local ranking weight registry after a successful deployment. LLM
  refinement and its categorical preference context remain disabled by default; the latter needs a
  field-level trust-boundary approval before it can be enabled.
- Updated the v0.2.0 plan after the arXiv outage and release-readiness review. Corpus size now controls
  uncertainty reporting rather than a fixed release gate, while automatic tuning remains disabled;
  the evolving corpus is evaluated through immutable pinned snapshots.
- Required LLM judging and explanation to receive complete normalized titles and abstracts, with
  deterministic whole-record batching, bounded retries/cost, and explicit oversized-record handling
  replacing character truncation.
- Expanded V020-M8 release hardening to cover browser schema v4 execution, arXiv retry spacing and
  validated-pool degradation, strict state restoration, deploy/state reconciliation, explicit ranker
  rollback, and confirmed ranking/cache/metric correctness defects.
