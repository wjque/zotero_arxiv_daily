# v0.2.1 Quality-First Ranking and Validation

- **Target version:** v0.2.1
- **Predecessor:** [v0.2.0 Interest-Based Screening and Feedback Foundation](v0.2.0-personalized-ranking-quality.md)

## Objective

Deliver a quality-first daily recommendation workflow that combines personal relevance with bounded,
inspectable public scientific and reproducibility evidence, learns an explicitly approved quality
reference profile from curated evidence and explicit feedback, and supports safe no-publish validation
runs during rapid production debugging.

## Scope

- Use the versioned production weights: interest `0.40`, recency `0.05`, watched identity `0.10`,
  scientific quality `0.35`, and project/repository availability evidence `0.10`.
- Include bounded public HTTPS project-page reachability in coarse screening and a graded public
  implementation-material signal in fine screening.
- Assess bounded public paper sections covering method, implementation or evaluation, and limitations
  when available; preserve explicit uncertainty when evidence is absent or unavailable.
- Build a reviewable, versioned quality reference profile from explicitly approved evaluation papers
  and explicit reading feedback, covering research problems, methodological expectations, evidence
  standards, motivations, and tolerated limitations.
- Promote recommendation history only after a successful public deployment and preserve exactly-once
  impressions.
- When less than 24 hours have elapsed since the previous successful Pages deployment, perform a
  metadata-only validation run without publishing or invoking a model.

## Non-Goals

- Sending raw Zotero records, notes, annotations, PDF content, collection names, or feedback prose to
  a remote provider.
- Executing, cloning, or trusting public repository code; repository evidence is not proof of
  correctness, reproducibility, licensing, security, or maintenance.
- Treating unavailable paper, project-page, repository, or data evidence as a negative scientific
  claim.
- Allowing a model to control candidate identities, URLs, persistence, deployment, scoring weights,
  or security policy.
- Updating the Pages site, recommendation history, impressions, pending publication state, or
  deployment receipt during a sub-24-hour validation run.
- Automatic quality-profile approval, automatic weight activation, or using absent feedback as a
  negative signal.

## Milestones

### V021-M1 Published-History Integrity

Only a successfully deployed batch advances the recommendation-history state used to suppress recent
papers. Failed, prepared, reconciled, and metadata-only runs retain the prior published history.

**Acceptance:** Deterministic tests cover successful deployment, failed deployment, failed state
persistence, reconciliation, repeated execution, and rollback. A paper in a successful batch is
excluded for the configured suppression window, while an unpublished batch never suppresses a paper.
Impressions remain exactly once per successful publication.

### V021-M2 Quality-First Coarse Screening

Coarse ranking applies the declared production weights to available interest, recency, watched-identity,
and bounded project-page reachability evidence. The result remains inspectable, deterministic, and
bounded before model evaluation.

**Acceptance:** Unit and contract tests verify the declared weights, availability-aware handling of
unknown evidence, approved HTTPS URL validation, redirects, status outcomes, timeouts, caching, and
stable ordering. Public reachability failure cannot block a batch or become a scientific-quality claim.

### V021-M3 Evidence-Bounded Fine Screening

Fine screening evaluates public scientific evidence from available method, implementation/evaluation,
and limitations sections, plus graded public implementation-material evidence from an explicitly linked
project or repository. It reports quality, uncertainty, evidence provenance, and reproducibility
evidence separately.

**Acceptance:** Offline fixtures cover section absence, malformed documents, bounded extraction,
prompt injection, unavailable sources, repository structures with documentation only, implementation
material, and declared data or evaluation material. Model outputs must be complete, schema-valid,
evidence-bound, and unable to introduce identifiers or URLs. Missing evidence is represented as
unknown, and no repository code is executed.

### V021-M4 Quality Reference Profile

The system produces a versioned, reviewable quality reference profile from explicitly approved
evaluation examples and explicit feedback. The profile informs scientific-quality assessment without
altering interest topics or treating silence as feedback.

**Acceptance:** Tests cover input allowlists, empty and malformed evidence, versioned encrypted
persistence, approval and rollback, repeated generation, and prompt-boundary validation. A production
canary records only privacy-safe aggregates and demonstrates that the approved profile is referenced
without exposing private Zotero content or feedback prose.

### V021-M5 Metadata-Only Validation Runs

A run started less than 24 hours after the previous successful Pages deployment refreshes allowed
metadata and records validation evidence without model calls or any user-visible publication change.

**Acceptance:** Integration tests verify the 24-hour boundary, retry behavior, missing deployment
history, and repeated validation runs. They prove that validation runs do not build or upload a site,
deploy Pages, alter recommendation history or impressions, or create pending publication state, while
their encrypted metadata and privacy-safe manifest remain inspectable.

### V021-M6 Release Safety

The release preserves backward readers, encrypted protected state, previous usable Pages output,
bounded external calls, deterministic recovery, and the v0.1.2 rollback path.

**Acceptance:** Formatting, lint, strict typing, offline unit/contract/integration tests, migration
tests, package and static-site builds, browser tests, artifact inspection, and security checks pass. A
production canary verifies full publication and a sub-24-hour validation canary verifies no Pages or
user-visible state change.

## Stage Acceptance

v0.2.1 is releasable when V021-M1 through V021-M6 pass, the new persisted formats are migrated and
rollback-tested, and an operator confirms both the quality-first published batch and the metadata-only
validation run satisfy their respective privacy, recovery, and deployment boundaries.
