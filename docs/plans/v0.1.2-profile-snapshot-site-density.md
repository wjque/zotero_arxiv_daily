## Objective

Replace the opaque Zotero library revision shown on the site with a timestamped profile snapshot
that has direct user meaning, and reduce the visual prominence and density of batch-status metadata.

## Acceptance Criteria

- New remote profiles retain an aware UTC source-library synchronization instant.
- New publishable data displays that instant as `Profile snapshot` in `Asia/Shanghai`; it never
  exposes the opaque Zotero revision number.
- Existing remote-profile v1/v2 and publishable-site v1/v2 data remain readable and omit unavailable
  snapshot information safely.
- Batch status uses compact typography, spacing, borders, and metadata layout while retaining all
  applicable generation, artifact, and workflow information.
- Full formatting, lint, strict typing, offline tests, package build, static-site build, and artifact
  inspection pass before deployment.

## Scope and Non-goals

Scope includes local synchronization metadata, remote-profile v3, publishable-site v3, adapters,
static-site rendering, tests, and documentation. It does not change ranking, model prompts, raw
Zotero sharing, browser secrets, historical recommendation data, or the scheduled workflow policy.

## Architecture and Migration

`ZoteroStore` records the successful local synchronization instant beside its internal revision.
Remote-profile v3 projects that non-sensitive timestamp, and publishable-site v3 carries it to the
browser. v1/v2 readers adapt missing timestamps to `None`; the UI omits the field rather than
inventing a time. Existing opaque revisions remain internal synchronization state only.

## Risks, Privacy, and Recovery

The timestamp reveals only when a profile source last synchronized, not Zotero items, notes,
annotations, identifiers, or profile content. If legacy profiles are not rebuilt, the site omits the
snapshot. Rollback is a code revert; old profile and publishable readers remain supported.

## Verification Strategy

Test timestamp creation and validation, legacy profile/publishable migrations, profile-to-site
projection, compact asset content and size budgets, malformed timestamps, and encrypted/public
site builds. Run the full offline gate and inspect generated artifacts before an approved production
deployment.
