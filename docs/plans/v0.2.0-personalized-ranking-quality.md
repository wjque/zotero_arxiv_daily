# v0.2.0 Interest-Based Screening and Feedback Foundation

- **Target version:** v0.2.0
- **Authorized scope revision:** 2026-08-06
- **Predecessor:** [v0.1.2 Profile Snapshot and Compact Status](v0.1.2-profile-snapshot-site-density.md)

## Objective

Deliver a reliable initial screening system that uses the complete local Zotero library to select a
personalized arXiv shortlist, applies a bounded preliminary quality review, and accumulates explicit
per-paper reading feedback for later versions. v0.2.0 establishes a usable collection loop; it does
not claim that the initial corpus or offline metrics are mature enough to optimize ranking quality.

## Scope

- Build a privacy-bounded interest profile from the complete local Zotero library.
- Coarse-rank public arXiv candidates using the existing interest score, recency, and exact watched
  author or institution matches. Collected feedback must not affect v0.2.0 ranking.
- Fine-rank the bounded coarse shortlist using a model's preliminary scientific-quality assessment
  from the complete title and abstract, plus a deterministic signal that an abstract-supplied project
  page uses an approved public HTTPS host and is reachable within bounded network limits.
- Treat project-page reachability as an initial open-source proxy, not proof of source availability,
  licensing, reproducibility, correctness, or maintenance. Missing or unavailable evidence must not
  become a negative quality claim.
- Generate factual summaries, specific recommendation reasons, and limitations only for final papers.
- Collect explicit per-paper daily reading feedback and successful-publication impressions in
  encrypted protected workflow state without interpreting missing feedback as negative.
- Preserve backward readers, deterministic repeated runs, the previous usable site on failure, and an
  explicit rollback path to v0.1.2 behavior.

## Non-Goals

- Using feedback to change ranking, topics, authors, institutions, prompts, or weights in v0.2.0.
- Treating NDCG, negative-label rate, Recall, token reduction, latency improvement, or relative cost
  improvement as v0.2.0 release thresholds.
- Automatic weight tuning, production activation from offline metrics, or statistically conclusive
  recommendation-quality claims.
- Verifying that a reachable project page contains source code or that a paper is truly open source.
- Verifying mathematical correctness, novelty, empirical claims, or reproducibility from an abstract.
- Searching for repositories by title or author, fetching repository contents, or executing paper code.

## Milestones

### V020-M1 Interest-Only Coarse Screening

The production coarse shortlist uses only interest, recency, and watched-identity signals. Explicit
feedback, impressions, scientific-quality evidence, reproducibility evidence, and context evidence do
not affect the initial shortlist.

**Acceptance:** Deterministic tests show that changing feedback while holding candidates, profile,
time, and watched identities constant cannot change coarse scores or ordering. Interest, recency, and
exact watched-identity matches remain inspectable and the bounded shortlist contains at most the
configured candidate limit.

### V020-M2 Preliminary Quality Fine Screening

The bounded coarse shortlist receives a model assessment based on complete titles and abstracts.
Fine ranking combines the coarse signals with uncertainty-discounted preliminary scientific quality
and an independently validated project-page reachability signal extracted from the abstract.

**Acceptance:** Offline tests cover complete-record prompts, malformed model output, unavailable
quality dimensions, link extraction, approved-host validation, bounded reachability checks, redirects,
timeouts, cache reuse, and provider failure. Missing or failed project evidence cannot block the batch
or create a negative open-source claim. A bounded production canary produces reviewable summaries,
reasons, limitations, quality, uncertainty, and project-page evidence without exposing private data.

### V020-M3 Daily Feedback Foundation

The browser records explicit per-paper actions and exports one validated batch for ingestion. The
workflow stores append-only outcomes and successful-publication impressions in encrypted protected
state. Feedback remains accumulated evidence for v0.2.1 or later and is not consumed by the v0.2.0
ranker.

**Acceptance:** Tests cover every supported action, malformed input, duplicate ingestion, missing
feedback, repeated papers, failed deployment, encrypted persistence, and recovery. A repeated run
creates no duplicate impression or outcome events, and silence is never stored as a negative.

### V020-M4 Release Safety

The release candidate preserves schema compatibility, privacy, bounded external calls, deterministic
state transitions, previous-site preservation, encrypted state, browser rendering, and rollback.

**Acceptance:** Formatting, lint, strict typing, offline tests, migrations, package build, static-site
build, browser end-to-end tests, and artifact inspection pass. A production canary and rollback
rehearsal pass, the changelog and operating documentation describe the delivered behavior, and the
immutable `v0.2.0` tag and GitHub Release identify the verified commit.

## Stage Acceptance

v0.2.0 is releasable when V020-M1 through V020-M4 pass and an operator confirms from the production
canary that the generated batch is a useful interest-based reading shortlist with no material factual,
privacy, or recovery defect. Aggregate ranking metrics remain recorded for future comparison but do
not approve or block this release.
